# T1 — TD vs MC vs hybrid value targets on identical frozen data

Date: 2026-08-18. Task: BiGym `sandwich_remove`. Machine: local, GPU 0 only
(`GPU-79eb6469-…`, EGL 4), arms run strictly sequentially.

## What this experiment is for

In this project you cannot read value quality off rollout success. Behaviour is
pinned by the BC hinge and by self-imitation, and every online arm changes its
own data distribution through exploration. So when `mclb` (max(TD, MC)) scored
51/65 against a 72 baseline on `move_plate`, we could not say whether the value
operator was worse, whether the data mix was worse, or whether the hinge simply
overrode both.

T1 removes both confounds. One frozen policy generates ONE dataset. Every arm
then trains **from scratch**, offline, on that same buffer, for the same number
of gradient updates, with the same seed and the same architecture. The only
thing that differs is the operator that produces the critic's regression
target. Nothing is judged by rollout success; everything is judged by probes
that read the critic directly.

## Headline

- **TD is sharp and well calibrated exactly on the demonstration manifold and
  nowhere else.** Off the demos its value surface is almost flat, and it is
  uniformly over-optimistic: it gives states drawn from *failed* episodes an
  average Q of 0.569 when their true return is exactly 0. Its ability to tell a
  doomed state from a good one is close to a coin flip (AUC 0.559).
- **Pure MC is dramatically better calibrated and does condemn failure**
  (AUC 0.723, Q on failed states 0.121 vs 0.215 on successful states), exactly
  as pre-registered — but it buys this by behaving like behaviour cloning in
  value space: its sharpness is concentrated on demo states and it is *flatter*
  than TD everywhere else.
- **max(TD, MC) is TD where it matters.** On demo states it inherits MC's
  sharpness (best fine-level agreement and largest Q-span of any arm, healthy
  chunk ranked top in 100% of demo probes). Off the demo manifold the `max`
  almost always selects the TD branch, so its calibration error (MAE 0.40–0.55)
  and its over-optimism (Q ≈ 0.55–0.62) are TD's. That is a direct mechanical
  explanation for why the `mclb` arms produced no rollout gain: on the states
  where a rollout actually goes wrong, `max(TD, MC)` *is* the TD critic.

### Two properties of this data that drive everything below

Reward is a single `+1` at success and nothing else (0.111% of steps are
non-zero). With `gamma=0.99` and ~400-step episodes that means:

- Every state of every **failed** episode has an MC return of *exactly* 0 —
  41 of the 120 training episodes, 24k transitions.
- In **successful** episodes, 37% of states have an MC return below one C51
  atom (support `[-2, 2]`, 51 atoms, atom width 0.08) and 54% below two atoms.
  The MC target only rises above one atom in the last ~250 of ~400 steps.

So a pure-MC target is numerically indistinguishable from "failure" over
roughly 60% of the collected transitions. TD has the same fixed point, but it
does not have to represent that fixed point through per-state sample returns.

### Two deviations from the brief, both deliberate

**1. `dense_return_q_target` is not a pure-MC target, so it is not the MC arm.**
The brief proposed `dense_return_q_target=true` for the MC arm. Reading
`robobase/method/cqn.py:1445-1520`, that flag does something else entirely: it
switches the critic loss from "train the chosen bin toward the target" to a
*dense action-coverage* loss that trains **all** bins — the recorded action's
bin toward whatever the upstream target is, and every unchosen sibling toward
`unseen_return_floor_value`. The upstream target is still TD unless
`mc_lower_bound_target` is also set (which its own validation demands when
`dense_return_positive_only=true`, `cqn_as.py:1594-1602`). It changes *which
actions get supervised*, not *what the return target is* — the wrong axis for
T1, and it would have confounded the operator with an action-coverage change.

The correct pure-MC knob in this codebase is `mc_return_weight` (`cqn.py:1674-1693`):
it projects the completed-episode discounted return onto the C51 support and
cross-entropies the executed action's own head against it. Setting
`critic_lambda=0` removes the TD cross-entropy entirely, leaving MC regression
plus the BC hinge. Verified in `pretrain.csv`: for the `mc` arm
`critic_loss − mc_return_loss` is exactly the BC term, and `mc_return_mae`
falls to 0.03–0.046.

**2. All arms carry `mc_return` in the replay signature.**
`_mc_return_anchor_enabled` (`workspace.py:297`) only stores `mc_return` when an
MC knob is on, and the storage signature is part of the shared-demo-cache key.
Without intervention the TD arms would have used a *different* demo cache from
the MC arms. To keep the frozen data byte-identical, TD-family arms set
`mc_return_weight=1e-9` — zero to float32 precision (the logged
`mc_return_loss` is exactly `0.0`), but enough to force the same storage
signature. All five arms therefore share one demo cache, one storage signature,
one batch layout, and one sampling RNG stream.

**3. The exploration dose is not the source arm's.** The brief asked for
"as-trained exploration". The source config has `bin_explore_probs: null`, so
train-mode rollouts would have been indistinguishable from greedy and the
dataset would have contained no genuinely off-policy states. We instead used the
two doses from this project's own dose-response ladder
(`scripts/eval_explore_dose.py`): `asis` and `x4`. Both produce real off-manifold
data — success falls 79% → 52% → 36%, exploration fires on 19% and 48% of steps,
and mean nearest-demo distance rises from 2.3 (greedy states) to 3.7 (explore
states) to 7.3 (failed-episode states).

## Probes

All probes are computed from stored transitions with no environment and no
rollouts (`scripts/t1_value_probes.py`). Observations are frame-stacked exactly
as the replay buffer does; action chunks are sliced and edge-padded exactly as
the replay buffer does. The critic is scored with its **online** parameters
(`params["critic"]`), using `_critic_logits_per_level`, which teacher-forces the
coarse-level zoom on the recorded action's own bins — so per-level agreement
means "given the recorded action's coarser bins, does the critic's argmax at
this level pick the recorded bin?". 600 probe states per group.

Groups: `demo` (demonstration states), and three held-out groups drawn from the
30 held-out collected episodes: `heldout_success`, `heldout_explore` (asis/x4
blocks) and `heldout_fail` (states from failed episodes).

## Interpretation against the pre-registered prediction

**Prediction: "pure MC behaves like value-space BC — sharp on successful
trajectories' states, condemns recoverable states via 0-return failures."**
Confirmed on both halves.

*Sharp where the demos are:* MC's Q-span on demo states at the two coarse levels
is 1.95 / 1.52, more than double TD's 0.86 / 0.72, and its healthy-chunk-ranked-top
rate on demo states is 0.985 against TD's 0.755. Its calibration on demo states
is near-perfect (r = 0.990, MAE 0.045 against a mean target of 0.260).

*Flat where they are not:* on held-out policy states MC's coarse Q-span drops to
0.35 / 0.15 — *below* TD's 0.52 / 0.24. So the MC critic is not "generally
sharper"; it concentrates all of its discrimination on states that look like the
data it could label confidently, and abstains elsewhere. That is exactly what
value-space behaviour cloning looks like.

*Condemns:* MC gives failed-episode states 0.121 against 0.215 for successful
ones and prefers a nearest-demo action over the executed failing action in 69%
of failure probes. TD prefers the executed failing action in 81% of the same
probes. Whether MC's condemnation is *correct* is not something this experiment
can settle — many of those states were still recoverable, and MC's target says 0
purely because that particular trajectory did not recover. The over-condemnation
risk in the prediction is therefore real but not directly measured here.

**Prediction: "pure TD is noisier but supports stitching."** Not supported in
this data. TD is not noisier — it is *flatter and uniformly optimistic*. Off the
demo manifold its Q sits at 0.56–0.59 regardless of whether the state came from
a successful episode (true return 0.233), an explore episode (0.096) or a failed
one (0.000). Its success-vs-failure AUC is 0.559. If TD were stitching, we would
see it separate recoverable states from doomed ones better than MC; it separates
them worse. What we actually see is textbook off-support over-estimation: the
`max`-over-bins bootstrap keeps propagating the largest available value into
states whose realised outcome was zero, and the BC hinge only pins the surface
down on the ~15% of the buffer that is demonstration.

**Prediction: "max(TD, MC) gives no rollout gain."** T1 supplies the mechanism.
`mclb` gets the best demo-manifold numbers of any arm (fine-level agreement
0.907 vs TD 0.985 / MC 0.739; Q-span at the finest level 0.620, the largest of
any arm; healthy chunk ranked top in **100%** of demo probes). But on all three
held-out groups its Q (0.550–0.617), its calibration error (MAE 0.396–0.550) and
its correlation are TD's, not MC's, and its AUC (0.658) sits between. The reason
is structural: `max(TD, MC)` can only ever *raise* the target, and off the demo
manifold TD is already the higher of the two, so the MC branch never binds
exactly where the over-estimation lives. Any benefit MC has to offer is
mechanically excluded from the region where rollouts fail.

**The resolution-vs-horizon problem is not an operator problem.** All three arms
must represent a value function whose true range over 60% of the buffer is
narrower than a single C51 atom. On demo states TD's own MAE is 0.141 against a
mean target of 0.260 — over half the signal. Choosing between TD and MC does not
address this; changing `gamma`, the support, or the reward shaping would. This
is the most actionable thing T1 surfaced that was not on the pre-registered
list.

## Limitations

- **One seed per arm.** Probe statistics are averages over 600 states, which is
  far tighter than a 50-episode rollout estimate, but seed-to-seed variation in
  the trained critic is not measured. The TD/MC gaps reported here (AUC 0.559 vs
  0.723, failure-state MAE 0.569 vs 0.121) are large enough that a single seed is
  informative; the `mclb`-vs-`td` differences on held-out groups are small enough
  that they should not be read as ordered without a second seed.
- **Demonstration states are in-training for every arm.** The `demo` group
  measures fit, not generalisation. It is directly comparable across arms (they
  all saw the same demos the same number of times) but it is not a held-out
  measurement.
- **25,000 updates, not 100,000.** These critics are trained to roughly a
  quarter of production budget. Every arm's demo-state agreement was still
  rising at 25k (TD 0.55 → 0.98 at the finest level between 5k and 25k), so the
  ordering could still move.
- **No rollout readout.** The optional restricted-decode rollout (probe e in the
  brief) was not run; the GPU budget went to the fifth arm instead.
- **"Nearest demo action" is a proxy.** At failed-episode states the nearest demo
  state is far away (mean L2 7.27 in normalised low-dim space), so the
  nearest-demo chunk is not guaranteed to be a good action there. The absolute
  gaps in probe (d) are small for every arm; only the *direction* of the
  preference is interpretable.
