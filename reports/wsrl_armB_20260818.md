# Arm B — WSRL 阶段撤锚 (staged unanchoring) on CQN-AS / sandwich_remove

状态: **已完结** (2026-08-18). 4 个 run 全部跑满, 判决见 §8。

**一句话**: 预登记预测被**证否**。WSRL 的 warmup + 高 UTD 重校准
一点没用 —— 崩溃就发生在"重校准"这一步本身, 而且换成 0% on-policy
数据的冷撤对照, 衰减曲线完全一样; 同协议只把 hinge 留着的对照
则跑到 val50 0.74 (底座 0.70)。撤锚崩溃不是分布错配的 seam transient,
是目标函数失去了唯一给未执行 sibling bin 施力的项。

---

## 1. 预登记的问题与预测

已确立事实 (lab record): 在线训练中把 DQfD BC hinge 冷撤 (`bc_lambda -> 0`)
会在 ~1k 次更新内摧毁 critic。参考指纹取自 `combined_sandwich` 的
`weansw` 双 seed (`step_linear(1.0,0.0125,50000,0.0,20000)`, λ 在 70k 精确归零):

| run | 65k (λ≈0.0031) | 69k (λ≈0.0006) | **70k (λ=0)** | 72k | 76k | 80k |
|---|---:|---:|---:|---:|---:|---:|
| s1 `bc_sibling_q_span` | 0.324 | 0.319 | **0.0069** | 0.0031 | 0.0017 | 0.0008 |
| s1 `bc_agreement` | 0.770 | 0.774 | **0.316** | 0.405 | 0.400 | 0.290 |
| s1 `bc_binding_rate` | 0.592 | 0.595 | **0.9996** | 1.000 | 1.000 | 1.000 |
| s2 `bc_sibling_q_span` | 0.408 | 0.347 | **0.0084** | 0.0043 | 0.0017 | 0.0008 |
| s2 `bc_agreement` | 0.822 | 0.812 | **0.462** | 0.414 | 0.348 | 0.296 |

(路径 `exp_local/cqn_trunc_arms/combined_sandwich/seed{1,2}_20260813weansw/train.csv`;
配套 val50: 65k = 66% → 70k = 0%。)

WSRL (arXiv 2412.07762, ICLR 2025) 主张这种崩溃是 **seam transient** —— 离线/
在线分布错配导致的 Q 重校准 —— 可以用四步流程避免:
(1) 冻结带锚策略; (2) 用它滚 warmup episodes 进 online buffer;
(3) **锚已关闭**的状态下在这批数据上做高 UTD 重校准; (4) 之后照常在线训练。

**预登记预测 (on record)**: warmup + 重校准之后, λ=0 的在线训练在 ≥20k
env steps 内 **不会崩溃**, rollout success 保持在带锚策略水平 (~70%)。

**崩溃判据 (预登记)**: `bc_sibling_q_span < 0.02` 持续 3k+ steps, 或
rollout success < 10% 持续 3k+ steps。

## 2. 实际跑的协议

底座 checkpoint: `exp_local/cqn_trunc_arms/official_sandwich_remove/seed2_20260805085944/eval_checkpoints/100000_checkpoint.pkl`
(hinged CQN-AS, `bc_lambda=1.0`; val50 seeds400 = 72%, val50 seeds450 = 70%,
sealed ep200 seeds800 = 80.5%; 该点 `bc_sibling_q_span = 0.747`)。

驱动脚本: `scripts/wsrl_staged_unanchor.py` (本次新写)。三个阶段跑在
**同一个进程、同一条不间断的环境流**里, 阶段切换只改
`cfg.online_update_after_steps` (被 `_online_updates_ready` 每步实时读取),
不重进 `_online_rl`, 所以没有任何 episode 被半路丢弃、
`Workspace._episode_rollouts` 累加器不会串台。

| 阶段 | 内容 | 参数 |
|---|---|---|
| P1 warmup | 冻结策略滚 rollout, **零梯度更新**; train-mode acting (as-trained: greedy over target critic + temporal ensemble + N(0, 0.01) 噪声, 无 bin explore) | 50 episodes, step cap 30000 |
| P2 recalibration | 纯梯度更新, **不走环境**; 锚已关闭 | 4000 gradient updates @ `num_update_steps=4` (1000 calls) |
| P3 online | 标准在线训练, 锚关闭 | 20000 env steps @ UTD 1 |

关键实现细节 (踩过的坑):

1. **λ=0 必须走 `bc_lambda_schedule`, 不能用 `bc_lambda=0`**。`cqn.py:1694`
   起的整块 BC 代码 —— *包括本实验唯一的读数 `bc_sibling_q_span` 等 bc_\* 诊断*
   —— 被 `if self.bc_lambda > 0.0 or use_bc_schedule:` 门住。静态 0 会把指标
   一起删掉 (历史 `wean0` run 的 train.csv 里就没有 bc_\* 列, 正是这个原因)。
   本臂用 `method.bc_lambda_schedule="0.0"`: `bc_weight` 变成一个被 trace 的
   0.0 常量, 梯度与静态 0 完全一致, 诊断保留。
2. **demo 必须在 `load_snapshot` 之前载入**。`Workspace._load_demos()` 在
   `self._snapshot_loaded` 为真时直接 return; 顺序搞反会得到两个空 buffer,
   正是 `cqn-rline.md` 890 记录的 params-only warm-start 惨案。
   本脚本顺序: 构造 → `_load_demos()` → `load_snapshot(..., load_replay_buffer=False)`
   → `configure_stages()` → `_online_rl()`。日志里可核对
   `[wsrl] demos loaded: online=9445 demo=9445`。
3. `WorkspaceFast.__init__` 原本不接受 `work_dir`, 加了一个默认 `None` 的
   透传参数 (`robobase/workspace_fast.py`), 对 `train_fast.py` 完全向后兼容。

### 已知偏差 (deviations), 必须记在案

- **优化器状态丢失**。底座是 params-only 的 `eval_checkpoint`, 对应的
  `resume_state.pkl` 在 finalize 时被清理了, 所以 Adam moments 从零重建
  (日志有 `No optimizer state ... will be reinitialized` 警告)。这正是
  `weanfc` 事故 (params-only warm-start 单独把 flip_cup 41.5%/35.5% 砸到
  6%/2%, 4-9k 步, 与 λ 无关) 的同一条件 —— 因此本臂 **必须配一个 λ=1 的
  同协议对照**才能归因, 见 §4 (跑了, 结论: 不是这个原因)。
- **没有做 WSRL 的 "no data retention"**。WSRL 原文主张在线阶段完全丢弃
  离线数据; 本臂保留了 as-trained 的 demo 通道 (每个 batch 256 online +
  256 demo, 且 online buffer 起手就有 9445 条 demo transition)。理由: 已确立
  的崩溃基线就是带 demo 通道测的, 去掉它会同时改两个变量。代价: 本实验
  测的是 "warmup + 重校准" 这个 bundle, 不是 "不留离线数据"。
- **self-imitation 开着** (`use_self_imitation: true`, as-trained)。warmup 里
  成功的 episode 会被 relabel 成 demo=1 并进 demo buffer, 所以 warmup 结束时
  demo buffer 从 9445 涨到 22458。

而是"值的可比性" —— argmax 失去可分辨的排序信号。

## 4. 控制臂 C: 同协议、hinge 不撤 (`ctrl_lam1_20260818wsrlB`)

目的: 本臂的底座是 params-only 的 eval checkpoint, 优化器状态已被清理,
而本 codebase 有过 `weanfc` 事故 —— **params-only warm-start 单独就能把
flip_cup 从 41.5%/35.5% 砸到 6%/2%, 4–9k 步, 与 λ 完全无关**。所以

## 6. 冷撤对照 D: 无 warmup, 同样 4000 次重校准 (`cold_lam0_20260818wsrlB`)

Arm A 崩了、Control C 没崩, 归因已经清楚。剩下最后一个问题:
**warmup 那 22.7k 条 on-policy 数据到底起了没起作用?**

对照 D: 同一 checkpoint、同样优化器重置、同样 4000 次 UTD-4 更新、
λ=0, **但 warmup 只走 1 步就切阶段**, 所以重校准时 online buffer 里
只有 9445 条 demo (`buffer_size: 9445`, 日志已核对) —— 零 on-policy 数据。

### 7.0 独立 greedy 评测 (val50, seeds 450–499, 与底座同口径)

train-mode rollout 是训练流里顺手拿到的读数; 下面这组是实验室标准的
固定 seed、贪心、50 episode 评测 (`scripts/eval_cqn_as_snapshot_sweep.py`),
与底座 checkpoint 的 `val50_seeds450 = 0.70` 直接可比:

| checkpoint | val50 (seeds 450–499) |
|---|---:|
| 底座 100k (带锚) | **0.70** |
| A seed1 @125000 (seam +2268) | **0.00** |
| A seed1 @142732 (seam +20000) | **0.00** |
| A seed2 @141466 (seam +20000) | **0.00** |
| **C (λ=1) @142900 (seam +20000)** | **0.74** |

也就是说: 同一条流水线, 撤锚的两个 seed 在 seam 之后 2268 步就已经
50/50 全败; 不撤锚的对照跑完同样 24k 次更新后 **0.74 > 底座 0.70**。

三个消融把因果链锁死:

1. **不是 harness 伪影。** C 与 A 只差 `bc_lambda_schedule` 一个字符串, 其余
   (params-only warm-start、优化器重置、buffer 重启、warmup、4000 次 UTD-4
   重校准、20k 在线、seed) 全同。C 的 critic 越训越好 (固定探针 agreement
   0.983→0.992, span 0.770→0.810), rollout 0.60→0.70。所以 `weanfc` 那条
   "params-only warm-start 单独就能砸掉底座" 的先例**在本任务/本协议下不成立**,
   Arm A 的崩溃唯一可归因于撤 hinge。
2. **不是 seam / 分布错配。** 崩溃**发生在 P2**, 那时环境完全静止, batch 里
   的 online 数据 71% 是冻结带锚策略刚滚出来的 on-distribution rollout。
   WSRL 说要用来"重校准"的那批数据, 恰恰是崩溃发生的地方。
3. **warmup 数据没有任何作用。** D 的 online buffer 里 0% on-policy 数据,
   衰减曲线与 A 的两个 seed 在噪声内重合 (4000 更新后 0.0257 vs 0.0238/0.0297)。
   把 71% 的 buffer 换成 on-policy rollout, 崩溃速率不变。

### 7.1 崩溃的形态学 (三处独立读数一致)

- `critic_loss` **不发散**: A 从 0.216 单调降到 0.148 (seed2 0.160), C 稳在 0.240。
- `binding_rate → 0.999+` 且 `margin_gap → 0⁻`: chosen bin 与所有 sibling bin
  的 Q 挤成一个点。
- 固定探针 `chosen_q` **0.129 → 0.28** 同时 `span` **0.770 → 0.0032**:
  所有 bin 一起向上抬到一个共同值。critic 退化成"与动作无关的状态常数"。
- `agreement` 0.983 → 0.32: demo 动作不再是 argmax, 但也没有别的动作稳定
  胜出 —— 因为已经没有可分辨的差。

换句话说, 撤掉 hinge 之后死掉的不是 value 的**大小**, 是 value 的
**可比性 (action gap)**。这与 WSRL 论文描述的 "sudden Q-divergence /
unlearning of pretrained values" 是**不同的病**: 我们的 Q 没发散、
没被 unlearn, 它是被抹平了。WSRL 的处方 (warmup + recalibrate) 针对的是
分布错配引起的 Q 尺度重估; 对"没有 hinge 就没有 sibling 分离力"这个病
无效, 因为病根不在数据分布, 在**目标函数少了唯一制造 counterfactual
sibling 监督的那一项**。

### 7.2 为什么这个方向仍然可能有救 (机制上的下一步)

崩溃的直接原因是: 1-step TD 只监督**已执行的那个 bin**, 未执行的 sibling
bin 完全没有梯度约束, 于是它们自由漂向让 loss 最小的方向 —— 与 chosen bin
同值。hinge 是当前配置里唯一给 sibling 施力的项。所以能替代它的只能是
**另一种给 sibling 施力/或者不去问 sibling 的机制**:

- **不问 sibling**: In-sample / IQL 式 bootstrap 只在已执行 bin 上取 max
  (路线图臂 A) —— 从源头取消对未执行 bin 的依赖, argmax 时用支撑掩码
  限制候选集。本实验的形态学正面支持这条: 病在"未监督维度自由漂移",
  in-sample 把它从决策路径上摘掉。
- **给 sibling 施力但要校准**: Cal-QL 式带掩码的单侧下压 (只在 Q 超过
  behavior 参考值时压), 保住 action gap 又不制造假 gap。
- 已被证否的不要重试: 无掩码 unseen floor (Wave-1, −26.25)、
  MC lower bound、纯探索加剂量 (178B: 8× 探索强度 λ=0 照样 0/200)。

## 8. 判决

**预登记预测: 「warmup + 重校准之后, λ=0 在线训练在 ≥20k steps 内不崩溃,
success 保持在 ~70%」 —— REFUTED (证否), 双 seed 一致, 且证否是干净的
(有同协议 λ=1 对照排除 harness 伪影)。**

具体地:

- 崩溃判据 `span < 0.02` 在 seam 之后 768 (s1) / 1034 (s2) 步就触发,
  并持续到 20k 窗口结束 —— 远超 3k 的持续要求。
- 崩溃判据 `success < 10%` 在整个 20k 窗口内持续触发:
  s1 = 1/38 (2.6%), s2 = 0/39 (0%), 对比同一 run 内 warmup 阶段
  同口径的 32/50 (64%) 与 37/50 (74%)。独立 greedy val50 (seeds 450–499)
  在 seam+2268 与 seam+20000 都是 **0.00**, 底座同口径是 0.70,
  同协议 λ=1 对照是 0.74。
- 而且**崩溃早在进入在线阶段之前就完成了**: 4000 次重校准更新后 span
  已经是 0.0238 / 0.0297, 也就是说 WSRL 流程里被寄予厚望的第 (3) 步
  ——"在 on-policy warmup 数据上以高 UTD 重校准" —— 正是崩溃发生的地方。

**因此本臂的结论不是"WSRL 流程实现得不好", 而是"WSRL 对崩溃的机制诊断
在 CQN-AS 上不成立"**: 撤锚崩溃不是离线/在线分布错配造成的 seam transient
(D 证明 on-policy 数据一点不改速率), 而是**目标函数里唯一给未执行 sibling
bin 施加分离力的项被移除**造成的 action-gap 抹平。路线图 (`reports/
value_learning_roadmap_20260818.md` §四) 里 "臂 B = 零新代码、只要
schedule+resume" 的判断在工程上是对的 (确实零新方法代码), 但机制拟合度
判断 ("攻崩溃瞬态") 是错的 —— **本臂应从候选池中划掉, 不必再给 4 seed。**

顺带确立的两条可复用事实:

1. `weansw` 那种"λ 归零 → 1k 步内 span 塌"的现象**与优化器状态无关、
   与 buffer 内容无关、与 warmup 无关**; 它是撤 hinge 的确定性后果。
   本次在 3 个独立配置 (A-s1 / A-s2 / D) 下重复了 3 次, 加上历史
   `weansw` 双 seed, 一共 5 次一致的指纹。
2. **params-only warm-start 本身在本任务/本协议下是安全的**: Control C
   从同一个 params-only checkpoint 出发, 优化器全新、buffer 重启,
   跑满 24000 次更新 (4000 重校准 + 20000 在线) 之后 val50 = 0.74,
   高于底座 0.70。`cqn-rline.md` 记录的 `weanfc` 41.5→6% 事故因此
   **不能再当作"params-only warm-start 必然毁底座"的通则**。
   注意边界: 本结论只覆盖"起手 buffer 里已有 9445 条 demo"的情形
   (本协议四个臂都满足, 包括冷撤臂 D); weanfc 的失败条件是
   **空 buffer 上立刻开更新**, 那个条件本次没有复现, 也没有被证否。
